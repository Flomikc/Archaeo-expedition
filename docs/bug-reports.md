## BR-01: Тост исчезает слишком быстро

- **Приоритет:** средний
- **Тест-кейс:** связан с TC-04
- **Шаги воспроизведения:**
  1. В магазине нажать «Купить» на предмет, который не по карману.
  2. Засечь время отображения тоста «Мало монет».
- **Ожидаемый результат:** тост виден 2.5–3 секунды, пользователь успевает прочитать.
- **Фактический результат:** тост исчезает через 1.5 секунды — при быстром переключении внимания можно пропустить.
- **Причина:** в `HUD.showToast` жёстко задан таймаут 1500 мс, переданный по умолчанию.
- **Решение:** увеличить дефолтный таймаут до 2600 мс, добавить параметр duration при важных сообщениях.
- **Статус:** исправлено
- **Коммит:** b3676e7 (см. git log)
- **Повторная проверка:** 30.09.2026
- **Результат повторной проверки:** PASS
- **Связанный тест-кейс:** TC-04 (перепройден успешно)
- **Комментарий:** таймаут тоста увеличен до 2600 мс. Тост читается, пользователь успевает среагировать.

## BR-02: Кнопка «Купить» не блокируется сразу после клика

- **Приоритет:** средний
- **Тест-кейс:** связан с TC-03
- **Шаги воспроизведения:**
  1. Открыть магазин, иметь достаточно монет.
  2. Быстро кликнуть «Купить» дважды по одному предмету.
- **Ожидаемый результат:** второй клик игнорируется, кнопка блокируется до завершения операции.
- **Фактический результат:** оба клика обрабатываются, монеты списываются корректно (логика защищает), но кнопка на мгновение переключается в промежуточное состояние.
- **Причина:** в `HUD.renderShop` кнопка перерисовывается только после `refreshLaptopUI`, а между кликами остаётся активной.
- **Решение:** выставлять `btn.disabled = true` сразу в обработчике клика, до вызова `onBuyItem`.
- **Статус:** исправлено
- **Коммит:** b3676e7 (см. git log)
- **Повторная проверка:** 30.09.2026
- **Результат повторной проверки:** PASS
- **Связанный тест-кейс:** TC-03 (перепройден успешно)
- **Комментарий:** кнопка «Купить» блокируется сразу при клике. Двойная покупка невозможна — второй клик игнорируется.

## BR-03: Тень аномалии не соответствует её парению

- **Приоритет:** низкий
- **Тест-кейс:** визуальное наблюдение при TC-13
- **Шаги воспроизведения:**
  1. Наблюдать за аномалией в темноте с фонариком.
- **Ожидаемый результат:** тень от аномалии мягкая и смещается вместе с парением.
- **Фактический результат:** аномалия парит, но тень остаётся статичной на полу — выглядит неестественно.
- **Причина:** тень рисуется статичным `ShadowGenerator`, привязанным к исходной точке, а не к парящему корню.
- **Решение:** отложено — `ShadowGenerator` не настроен в текущем MVP, это визуальный полиш для фазы 2.
- **Статус:** открыт (перенесён в фазу 2)
- **Коммит:** —

## BR-04: При быстром переключении вкладок ноутбука UI мерцает

- **Приоритет:** низкий
- **Тест-кейс:** ручное наблюдение при TC-03
- **Шаги воспроизведения:**
  1. Открыть ноутбук.
  2. Быстро переключаться между вкладками (Карта ↔ Магазин ↔ Артефакты).
- **Ожидаемый результат:** переход плавный, без мигания.
- **Фактический результат:** при быстрых кликах фон вкладки на мгновение становится пустым.
- **Причина:** в `HUD.setLaptopTab` сначала скрываются все панели, потом показывается нужная. Между этими операциями — один кадр пустоты.
- **Решение:** отложено — визуальный микро-баг, не влияет на функциональность. Можно исправить через CSS-класс `.tab-panel.active` без скрытия всех.
- **Статус:** открыт (перенесён в фазу 2)
- **Коммит:** —
