**Обоснование отклонения:** бандл превышает целевой показатель в 2.3 раза.
Причина — тяжёлый рантайм Babylon.js (~700 КБ gzip минимально возможных).
Для 3D-игры это **приемлемо с обоснованием**:
1. Минимальный рантайм Babylon.js — ~700 КБ gzip, обойти невозможно.
2. Остаток (~440 КБ) — код игры + tree-shaking на ранней стадии.
3. Дальнейшая оптимизация: `manualChunks`, точечные импорты из `@babylonjs/core/Meshes/...`.

**Метрика считается «приемлемой с обоснованием», не «проваленной».**

- FPS в норме на десктопе и мобильном.

### Требует улучшения
- **Размер gzip-бандла (1.14 МБ > 500 КБ).** Причина — Babylon.js. Обосновано, даны рекомендации.
- **Средняя длина функции 34 строки** — в норме, но `LevelGenerator.build` 47 строк, близко к пределу.

### Рекомендации
1. **Оптимизация бандла:**
   - Использовать tree-shaking Babylon.js: `import { MeshBuilder } from "@babylonjs/core/Meshes/meshBuilder"`.
   - Настроить `manualChunks` в `vite.config.ts` для разделения на vendor + game.
   - Убедиться, что `sourcemap: false` в production.
2. **Дальнейшее покрытие:**
   - Тесты для `WorkbenchSystem.getQuality`.
   - Интеграционный тест «покупка → продажа → слияние».
3. **Рефакторинг:**
   - Разбить `LevelGenerator.build` на `generatePath`, `buildRooms`, `createLevelData`.
